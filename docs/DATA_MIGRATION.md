# 数据迁移说明

## 原则

迁移先备份、再演练、最后应用。任何 Schema 删除操作之前都要保存完整本地状态和 SQL，并在独立目录完成恢复验证。备份目录不得提交到 Git。

## 阶段 1 迁移

可复用迁移脚本为 `drizzle/0002_single_user_no_files.sql`。

该脚本在旧 Schema 上按以下顺序运行：

1. 先检查 `users` 数量。多于一个账号时触发数据库约束并停止，且尚未执行表删除。
2. 删除 `shares`、`files`、`invites`。
3. 重建 `records`，保留记录内容、修订号和更新时间，去掉 `owner` 与多人外键。
4. 重建 `habits`，保留习惯定义和修订号，去掉 `owner` 与隔离索引。
5. 删除 `users.role`，保留账号、密码派生值、设置、月度重点和修订号。
6. 建立单用户日期索引与每天一条睡眠/餐饮记录的唯一索引。

阶段 0 的 `0000`、`0001` 迁移及元数据保持不可变。新建 D1 时依次应用前三个迁移即可得到阶段 1 Schema。

## 阶段 2 迁移

可复用迁移脚本为 `drizzle/0003_device_sessions.sql`。它只对 `sessions` 增加字段和索引，不重建或删除任何表：

1. 增加公开会话 ID、设备 ID 摘要、设备名称和 UA 摘要。
2. 增加创建时间、最近使用时间和撤销时间。
3. 为阶段 1 旧会话回填随机公开 ID；按原 7 天有效期推算创建和最近使用时间。
4. 建立公开 ID 唯一索引、用户有效会话索引和设备查询索引。

原 `token`、`user_id`、`expires` 保持原名和含义，因此阶段 1 代码仍能读取或删除旧会话。物理 Schema 中公开 `id` 保持可空是为了允许增量回填；阶段 2 应用代码对所有新会话强制写入非空随机 ID。

本地执行：

```powershell
npm run worker:db:init
```

脚本只使用本地 D1，并通过 `.wrangler/local-migrations.json` 避免重复应用。

## 已验证的数据保留范围

`work/migration-test.py` 会在临时目录建立旧版样本数据库，再依次应用阶段 1 和阶段 2 迁移。演练校验：

- 唯一账号与登录会话；
- 睡眠、学习、餐饮和习惯打卡记录；
- 运动、清洁、每日 SOP 与自定义习惯定义；
- 个人设置、模块显示偏好与月度重点；
- 数据库完整性和单用户索引；
- 多账号旧库会在破坏性操作前停止。
- 阶段 1 会话 token、账号和到期时间保持不变；
- 设备字段和公开会话 ID 正确回填；
- 阶段 1 的旧会话查询在增量迁移后仍兼容。

## 后续备份验收字段

自动备份与恢复只校验记录、习惯、设置、月度重点和由恢复数据重新计算的统计结果。
