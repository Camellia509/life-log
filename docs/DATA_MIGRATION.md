# 数据迁移说明

## 原则

迁移以“不丢记录”为最高优先级。任何删除表、字段或接口的操作之前，都必须先生成本地状态归档和完整 SQL，并在新目录完成恢复验证。原始备份不可被迁移脚本覆盖。

## 阶段 0 保留内容

当前数据库原样保存以下表：`users`、`sessions`、`records`、`habits`、`shares`、`files`、`invites`、`attempts`。当前 `.wrangler/state` 也完整归档，因此第一版仍可整体恢复。

阶段 0 不执行 Schema 迁移，不删除多人数据，不删除图片元数据，也不删除本地 R2 状态。

## 阶段 1 迁移边界

阶段 1 开始前再次生成备份。迁移程序必须先确认唯一保留的个人账号；如果发现多个真实账号或无法判断归属，立即停止并报告，不自动选择或删除。

确认账号后：

1. 保留该账号的睡眠、学习、餐饮和习惯打卡记录。
2. 保留全部习惯定义、设置、月度重点和模块显示偏好。
3. 删除邀请、亲友关系、分享授权及人数上限数据结构。
4. 删除所有用户图片元数据和本地图片对象，不迁移到 D1，也不迁移到其他存储服务。
5. 最后移除记录和习惯中的多人所有权字段，并重建单用户索引。

图片删除属于阶段 1 的预定行为，不在阶段 0 提前执行。

## 后续备份验收字段

自动备份与恢复只校验：

- 睡眠、学习、餐饮和习惯打卡记录；
- 运动、清洁和每日 SOP 项目；
- 个人设置和模块显示偏好；
- 各月重点；
- 使用恢复数据重新计算得到的月度统计结果。

不包含图片文件、图片元数据或图片哈希。
